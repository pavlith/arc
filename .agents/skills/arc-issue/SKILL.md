# Issue workflow
1. Reuse the active GitHub Issue (or create it before editing). Read scope, acceptance and labels; never create a second task tracker.
2. Inspect current code and only referenced contracts. Keep changes within the Issue; update labels if authorized.
3. Deliver an independently verifiable slice, record actual checks and link commits/PRs. `Refs #N` means partial; `Closes #N` requires complete acceptance.
4. Commit/push/PR only when authorized. Keep the report concise; see `AGENTS.md`.
